# PBRT 12장 한국어 본문 · 공통 리더 연결

## 이번 실제 범위

사용자가 첨부한 PBRT 4판 원문 ZIP의 12장 도입부, 12.1~12.6, 추가 읽기 설명, 연습문제 11개를 한국어로 번역한 초안입니다. 길잡이로 대체하지 않았습니다.

- 원문 텍스트 단위 429개: 한국어 374개, 문헌 검색을 위해 원어로 보존한 참고문헌 55개
- 원문 주석 번역 2개
- 본문과 별도로 표시하는 초보자 학습 도움·정정/조건 역주 39개
- 첨부 PDF의 그림 33개: 원문 페이지와 추출 좌표를 기록했습니다. 대화형 그림의 모든 상태가 아니라 PDF에 보이는 정적 상태입니다.

원문 문단과 수식·코드·참조 토큰을 대조합니다. 코드 조각과 수식은 첨부 원문에서 복원합니다. 독립 전문 감수 완료나 책 전체 완료를 뜻하지 않습니다. **13~16장·부록 본문 번역과 1~8장 전수 검수는 남아 있습니다.**

## GitHub와 사용자 PC의 상태를 구분합니다

이 디렉터리에는 번역 JSON, 원문/번역 체크섬, 그림 추출 정보가 들어 있습니다. `tools/pbrt/prepare_ch12.py`는 이 자료와 첨부 원문으로 기존 공통 앱이 읽는 native 수업 데이터를 만듭니다.

현재 앱은 native 수업을 기존 목차·본문 검색·읽기 위치·메모·북마크·학습 기록에 연결합니다. 별도의 HTML 리더를 실행할 필요가 없습니다. **다만 git pull만으로 개인 PC에 원문이나 생성된 이미지가 생기지는 않습니다.** 처음 한 번 아래 방법 중 하나로 로컬 본문 데이터를 준비해야 합니다. 클라우드 배포는 하지 않습니다.

### 방법 A — 생성된 9~12장 통합 데이터 설치

대화에서 제공한 `pbrt-native-ch09-ch12.zip`을 모두 풉니다. 프로젝트를 최신 main으로 갱신한 뒤, 압축을 푼 폴더의 설치 도구를 실행합니다.

```powershell
git pull --ff-only
py "C:\Downloads\pbrt-native-09-12\install.py" "C:\프로젝트\study"
py "C:\Downloads\pbrt-native-09-12\install.py" "C:\프로젝트\study" --apply
```

첫 실행은 변경 예정만 확인합니다. `--apply`는 기존 native 데이터를 백업한 뒤 9~12장 통합 데이터로 교체합니다. 이 묶음에는 9장 12개, 10장 8개, 11장 7개, 12장 9개의 도입부·절·추가 읽기·연습문제 페이지, 총 36개 수업 데이터가 들어 있습니다. **다른 native 장을 별도로 추가한 작업 폴더에는 전체 교체 대신 아래의 직접 생성/병합 절차를 사용하세요.**

기존 1~8장 소스나 앱 소스, Git 이력, 브라우저에 저장된 개인 메모는 변경하지 않습니다. 설치 결과에 백업/복원 ID가 출력됩니다. 설치 확인은 같은 명령에 `--verify`, 복원은 `--restore <출력된 ID>`를 지정합니다. 설치 후 파일을 수정했다면 복원 도구는 그 변경을 덮어쓰지 않고 중지합니다.

프로젝트 폴더에서 기존처럼 실행합니다.

```powershell
npm ci
npm run dev
```

이미 의존성이 설치되어 있고 lockfile이 바뀌지 않았다면 `npm ci`를 반복할 필요는 없습니다. 서재의 PBRT 목차에서 **번역 본문 · 초안**을 선택합니다. 기존 독자 강의·길잡이와 구분되어 표시됩니다.

### 방법 B — 첨부 원문으로 직접 생성

Python 3.10 이상을 사용합니다. 의존성 설치를 제외한 본문 생성은 네트워크를 사용하지 않습니다.

```powershell
py -m pip install -r tools/pbrt/requirements-native.txt
py tools/pbrt/prepare_ch12.py --source "C:\원문\pbrt-source.zip" --ch09-ch10 "C:\Downloads\pbrt-ch09-ch10-korean-translation.zip"
```

기존 9·10장 번역 ZIP을 함께 주면 앞의 빌더로 9~11장을 생성하고 12장을 추가합니다. 기본 출력은 `public/books/pbrt-4ed/native`입니다. 기존 출력이 있으면 중지합니다. 명시적으로 `--replace`를 주면 성공적으로 생성한 뒤에만 기존 출력 폴더를 백업하고 교체합니다.

이미 native 데이터가 있는 경우에는 기존 자료를 유지하며 12장을 더할 수 있습니다.

```powershell
py tools/pbrt/prepare_ch12.py --source "C:\원문\pbrt-source.zip" --existing-native "public\books\pbrt-4ed\native" --out "public\books\pbrt-4ed\native" --replace
```

기존 자료에 12장 ID가 이미 있으면 임의로 덮어쓰지 않고 중지합니다. `--ch09-ch10` 또는 `--existing-native`를 생략하면 12장만 생성하므로, 누적 데이터가 필요한 경우 위 명령의 옵션을 유지하세요.

## 실제 수행한 검증

1. 첨부 원문과 정규화 번역 데이터, 문단별 수식·코드·참조 토큰 대응 검사.
2. 원격 저장소의 실제 빌더로 원문 ZIP과 이전 9·10장 ZIP을 읽어 9~12장 native 데이터 36개를 누적 생성. 생성된 모든 수업 파일의 체크섬과 DOM ID, 이미지 경로 검사.
3. 12장 실제 본문 9페이지를 저장소 CSS로 메모리 내 렌더링. 320/390/768/1440px, 본문 24px의 36개 조건과 모바일 한영 대조 9개 조건, 총 45개 확인. 페이지 가로 넘침·그림 실패·SVG 참조 누락·런타임 오류가 없었습니다. 이 검사는 전체 앱 탐색 테스트가 아닙니다.
4. 실제 생성된 9~12장 데이터로 설치·재설치·검증·변경 감지·백업·복원 등 9개 시나리오 통과.
5. GitHub CI run 35433758768: 번역 체크, Python 가져오기 합성 테스트 11개, `npm ci`, 전체 `npm run build`, 실제 localhost의 브라우저 테스트 통과. 브라우저 테스트는 검사용 합성 수업으로 공통 메모·북마크·읽음·한영 표시·검색·History·LocalStorage·화면 너비를 검사합니다. 12장 전체 실데이터를 사용한 전체 앱 E2E나 사용자 Windows 실기기 검증과는 구분합니다.

첫 CI에서 12.5의 ‘장면의 바운딩’과 ‘장면 바운딩’ 한 글자 차이를 검출했습니다. 원격 파일을 검수본과 전체 대조해 의미와 토큰에 변화가 없는 이 차이만 확인한 후 체크섬을 일치시켰습니다. 검사를 끄거나 미완료 범위를 완료로 표시하지 않았습니다.
