# PBRT 9–11장 · 공통 리더 통합

## 이번 변경

기존의 별도 9·10장 리더 자료와 새 11장 본문을 공통 스터디 앱의 목차·검색·문단 메모·북마크·읽음·읽던 위치에 연결합니다. 서로 다른 책의 기록은 계속 분리됩니다. 미래의 다섯 책은 사용자가 자료를 지정할 때까지 중립적인 추가 예정 슬롯으로 표시합니다.

11장은 첨부 원문 스냅샷의 도입부, 11.1~11.4, 추가 읽기 설명, 연습문제에 대응하는 한국어 본문 초안입니다. 텍스트 단위 254개, 원문 주석 6개를 번역했습니다. 별도 학습 도움·정정 역주는 22개이며, 참고문헌 48개 항목은 원어를 보존했습니다. 그림 22개는 첨부 PDF의 해당 위치를 사용합니다. 여러 페이지에 나뉜 비교 그림은 함께 복원했습니다.

원문의 수식·코드 토큰은 임의로 바꾸지 않고, 정정이나 초보자 설명은 별도로 표시합니다. 11.2의 옌센 부등식에 따른 편향 방향, 널 산란의 생존/종료 확률 등은 역주로 설명합니다. 체크섬 검사는 의미 정확성에 대한 전문 감수를 대신하지 않습니다.

**책 전체 완료가 아닙니다. 12~16장과 부록의 실제 본문 번역, 기존 1~8장 전수 검수가 남아 있습니다.**

## GitHub 소스와 로컬 읽기 파일

저장소에는 공통 리더 연결 코드, 11장 한국어 원본 데이터, 원문/번역 체크섬, 그림 위치, 생성·설치 도구, 빌드/브라우저 검사 코드가 있습니다. 수식·그림까지 복원한 9–11장의 큰 JSON/이미지 결과물은 대화의 `study-native-pbrt09-11.zip`으로 전달합니다. 소스만 pull한 상태와 로컬 읽기 자료까지 설치한 상태를 구분하세요.

### 간단한 설치

1. 기존 프로젝트에서 `git pull --ff-only`를 실행합니다. 작업 중인 로컬 변경은 먼저 보존하세요.
2. 새 ZIP을 압축 해제하고 다음을 실행합니다.

```powershell
py "C:\압축해제\study-native-pbrt09-11\install.py" "C:\프로젝트\study"
py "C:\압축해제\study-native-pbrt09-11\install.py" "C:\프로젝트\study" --apply
py "C:\압축해제\study-native-pbrt09-11\install.py" "C:\프로젝트\study" --verify
```

첫 명령은 미리보기입니다. 설치기는 앱 소스나 Git을 수정하지 않고 `public/books/pbrt-4ed/native`만 설치합니다. 파일 체크섬을 전부 확인하며, 기존 폴더는 프로젝트 루트의 `.study-native-backups` 아래로 보존합니다. 변경된 파일이 있으면 복원 시에도 무작정 덮어쓰지 않습니다.

```powershell
cd "C:\프로젝트\study"
npm ci
npm run build
npm run dev
```

앱의 PBRT 목차에서 ‘번역 본문 · 초안’을 선택합니다. 별도 HTML 리더를 실행할 필요는 없습니다. `git pull`만으로 복원 이미지가 생기지는 않습니다. 새 데이터가 없거나 손상된 경우 기존 자료는 열리고 안내 메시지를 표시합니다.

복원은 설치 시 출력한 restoreId로 실행합니다.

```powershell
py "C:\압축해제\study-native-pbrt09-11\install.py" "C:\프로젝트\study" --restore "출력된복원ID"
```

### 원본 파일에서 직접 다시 생성

아래 방식은 새 설치 패키지를 쓰는 경우에는 필요 없습니다. 처음 첨부했던 원문 ZIP과 이전에 전달한 9·10장 통합 ZIP이 필요합니다. 본문 생성 과정에서는 네트워크를 사용하지 않습니다.

```powershell
py -m pip install -r tools/pbrt/requirements-native.txt
py tools/pbrt/prepare_native.py --source "C:\자료\원문.zip" --ch09-ch10 "C:\자료\pbrt-ch09-ch10-korean-translation.zip"
```

기존 출력이 있으면 덮어쓰지 않고 중지합니다. `--replace`를 명시하면 기존 결과 폴더를 백업합니다. 원문 스냅샷의 체크섬이 다르면 임의로 계속하지 않습니다. 원문 ZIP만으로 9장 한국어 번역을 새로 만들어 내는 도구는 아닙니다.

## 검증 범위

- 11장 원문 단위/수식·코드 토큰 대응 및 번역 데이터 체크섬 검사.
- 기존 코드 조각을 바꾸지 않는 가져오기 검사와 ID·링크·자산 경로 검사.
- 실제 27개 번역 페이지를 320·390·768·1440px, 본문 24px로 확인한 108개 격리 레이아웃 검사.
- 공통 메모·읽음·북마크·검색·코드 펼치기 및 외부 실행 코드 제거 검사.
- 별도로 GitHub Actions에서 **실제 프로젝트 `npm ci`와 `npm run build`**, localhost에 띄운 production build의 실제 History/LocalStorage 검사. 이 브라우저 CI에는 저작물 전체가 아니라 합성된 두 수업을 사용합니다.
- 설치기 미리보기·최초 설치·중복 설치·체크섬·복원·변조 거부·심볼릭 링크 거부 등 10개 시나리오.

108개 실제 번역 페이지 레이아웃 검사는 set_content/테스트용 URL·기록 객체에서 수행했습니다. 실제 localhost CI 검사는 네이티브 브라우저 기록과 저장소를 쓰지만 합성 콘텐츠로 수행합니다. 둘을 합쳐 ‘모든 실제 번역 페이지를 사용자 Windows PC에서 직접 검증했다’고 해석하면 안 됩니다. 독립적인 전문 번역 감수도 완료하지 않았습니다.

## 데이터 구조

`catalog.json`은 가벼운 수업 정보/검색 색인입니다. 실제 수식이 많은 본문은 각 수업 JSON으로 나누어 열 때 불러옵니다. 전체 목록을 먼저 검증한 다음 등록하고, 본문 로딩이 실패해도 다른 책을 숨기지 않습니다. SVG glyph와 DOM ID를 페이지별로 분리하고, 첨부 HTML의 스크립트/이벤트 속성/외부 SVG 참조를 실행하지 않습니다.
